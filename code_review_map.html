1 · Overview of Changes

Why the controller was replaced

A PI controller was the first approach. It failed because the wire's usable resistance span is only 1.2 Ω (8.82 → 7.62 Ω, 13.6% dR/R), and measurement noise reaches ±10–15% contraction at the 100 ms ADC cadence. Any KP large enough to reject disturbances caused full-scale oscillation; any KP small enough to be stable was too slow to reject the spring load.

A fuzzy controller with a wide deadband (12%) tolerates the noise floor while still driving hard when error is large.

Iteration path

  1. PI — oscillated at all KP values tested (0.3, 0.1)
  2. Discrete fuzzy — settled better; hard 0% cut on slight overshoot caused spring snap visible in hardware
  3. Fuzzy + soft-cool — added 10% intermediate; still stepped
  4. Piecewise linear interpolation — smooth ramps between control points; currently deployed

2 · MW_CLTick — PI → Fuzzy Interpolated Controller REWRITE

Limbs/muscle_wire.c · Limbs/muscle_wire.h

What changed

BEFORE — PI controller
static float cl_integral = 0.0f;

// MW_CLTick:
float error = cl_target_pct - measured;
cl_integral += error * (CL_PERIOD_MS / 1000.0f);
float pwm_f = KP * error + KI * cl_integral;
// clamp → MW_SetPWM
AFTER — fuzzy interpolated
static float cl_prev_pct = 0.0f;

// MW_CLTick:
float error = cl_target_pct - measured;
float rate  = (measured > 0 && cl_prev_pct > 0)
              ? (measured - cl_prev_pct) : 0.0f;
cl_prev_pct = measured;
// piecewise linear ramps → MW_SetPWM

Helper: fz_lerp()

static float fz_lerp(float x, float x0, float x1, float y0, float y1)
{
    if (x <= x0) return y0;
    if (x >= x1) return y1;
    return y0 + (y1 - y0) * (x - x0) / (x1 - x0);
}

Control surfaces (heating vs. cooling)

Heating ramp (error ≥ 0, needs more contraction)

error < DEAD_PCT  →  HOLD_PWM  (flat)
DEAD → SMALL      →  lerp(LOW, MED)
SMALL → LARGE     →  lerp(MED, HIGH)
error > LARGE     →  HIGH_PWM  (flat)

Rate guard: if wire is already moving toward
target fast (rate > RATE_THRESH), blend toward
HOLD_PWM to avoid overshoot.

Cooling ramp (error < 0, above target)

|error| < DEAD_PCT  →  HOLD_PWM  (flat)
DEAD → SMALL        →  lerp(HOLD, SOFT_COOL)
SMALL → LARGE       →  lerp(SOFT_COOL, 0%)
|error| > LARGE     →  0%

Rate guard: if wire is already cooling fast
(rate < -RATE_THRESH), clamp to HOLD or
SOFT_COOL to avoid spring snap.

Tuning constants (current values)

CL_PERIOD_MS      300    // controller cadence (ms)
FZ_DEAD_PCT       12.0   // deadband — must exceed noise floor (~10%)
FZ_SMALL_ERR      20.0   // transition point low→mid drive
FZ_LARGE_ERR      35.0   // transition point mid→full drive
FZ_HIGH_PWM       35     // full drive (%)
FZ_MED_PWM        25     // medium drive (%)
FZ_LOW_PWM        20     // light drive (%)
FZ_HOLD_PWM       18     // hold/deadband PWM (%)
FZ_SOFT_COOL_PWM  10     // gentle coast-down PWM (%)
FZ_MIN_HOLD_TARGET 20.0  // targets below this use 0% in deadband
FZ_RATE_THRESH    10.0   // rate anticipation threshold (%/tick)
Tuning note: FZ_HOLD_PWM = 18% sits just above the measured activation threshold (~15–18%). If the wire creeps at a steady target, decrease HOLD_PWM by 1. If it relaxes away from target during the deadband, increase by 1. This is the most sensitive tuning parameter.
Char-wire data insight: 20% and 25% PWM both plateau at ~65% contraction — the wire's heating plateau. 35% PWM reaches ~100%. The useful control range is roughly 25–80% contraction. The heating time-constant τ ≈ 1.8 s; cooling τ ≈ 700 ms (spring-assisted, ~2.5× faster than heating).

3 · MW_Calibrate — Quality Warning Fix BUG FIX

Limbs/muscle_wire.c

The bug

Calibration emitted warnings referencing absolute Ω thresholds written for a ~20 Ω wire. This wire measures ~8.9 Ω cold. Every calibration run triggered the warning even on a perfect result.

BEFORE — wrong thresholds
if (cal_r_max < 12.0f) {
    print("R_max below 12 ohm; not relaxed");
    print("show-pwm R wire near 20 ohm first");
}
AFTER — relative dR/R check
float dr_r_pct = span / cal_r_max * 100.0f;
bool span_suspect = (dr_r_pct < 5.0f);
if (span_suspect) {
    print("span < 5% dR/R — may be noise");
    print("ensure wire was fully relaxed");
}
This wire achieves 13.6% dR/R (span 1.20 Ω / R_max 8.82 Ω). The 5% threshold gives comfortable margin. A suspect result would be span < 0.44 Ω on this wire.
Same fix applied to show-cal output — it now displays dR/R: 13.6% instead of the misleading absolute comparisons.

4 · MW_SetTarget — Zero-target Deadband Fix BUG FIX

Limbs/muscle_wire.c · Limbs/muscle_wire.h

The bug

With set-per 0, the controller computed error = 0 − 0 = 0 (measured was clamped to 0 when wire was fully relaxed), fell into the deadband, and applied FZ_HOLD_PWM = 18% continuously. The wire never fully relaxed — it sat warm at ~15–18% PWM indefinitely.

BEFORE — hold PWM always used in deadband
const float h = (float)FZ_HOLD_PWM;
// h = 18% regardless of target
AFTER — hold suppressed below min target
const float h =
  (cl_target_pct >= FZ_MIN_HOLD_TARGET)
  ? (float)FZ_HOLD_PWM : 0.0f;
// h = 0% when target < 20%

Rate guard for invalid→valid transition

BEFORE — phantom rate spike
float rate = measured - cl_prev_pct;
// when wire transitions from clamped 0
// to valid 21.7%, rate shows +21.7 phantom
AFTER — guarded
float rate = (measured > 0.0f && cl_prev_pct > 0.0f)
             ? (measured - cl_prev_pct) : 0.0f;
FZ_MIN_HOLD_TARGET = 20.0f means any target below 20% contraction behaves as "full off" in the deadband. This is intentional — the activation threshold is ~15–18% PWM, so holding at 18% with a near-zero target just keeps the wire warm for no reason.

5 · MW_CharTick / MW_CLI_DumpChar — Char-Wire Profiler NEW

Limbs/muscle_wire.c · Limbs/muscle_wire.h

Purpose

Automated 3-phase step-response test for characterising a specific wire's dynamics without manual intervention. Results are emitted as CSV for paste into a spreadsheet.

State machine

MW_CHAR_IDLE
  │  (char-wire N command)
  ▼
MW_CHAR_PRECOOL  ──── 15 s at 0% PWM ────────────────── wait for stability
  │
  ▼
MW_CHAR_HEATING  ──── up to 30 s at N% PWM ──────────── wait for stability
  │
  ▼
MW_CHAR_COOLING  ──── up to 30 s at 0% PWM ──────────── wait for stability
  │
  ▼
MW_CHAR_DONE     ──── "dump-char" to emit CSV

Stability detection

A rolling window of CHAR_STABLE_COUNT = 10 samples is maintained. Stable when the range (max−min) within the window is < CHAR_STABLE_PCT = 5.0% contraction. Sampling cadence: 200 ms.

Buffer

MW_CharSample_t char_buf[512];   // ~102 s at 200 ms cadence
// { uint32_t time_ms, uint8_t phase, uint8_t pwm_pct,
//   float r_wire, float contraction }

CLI usage

char-wire 25      // run test: precool, heat at 25%, cool to rest
dump-char         // emit CSV (after char-wire completes)
Char-wire must not run while closed-loop is active. MW_CharTick takes direct PWM control. Calling char-wire while set-per has an active target will produce confusing results — the CL tick and char tick will fight over PWM. Consider adding a guard that aborts char if cl_target_pct ≥ 0.
Key findings from hardware runs:
  • Activation threshold: ~15–18% PWM (below this, no movement)
  • 20% and 25% PWM both plateau at ~65% contraction (heating plateau)
  • 35% PWM reaches ~100% contraction
  • τ_heat ≈ 1.8 s · τ_cool ≈ 700 ms (spring-assisted, 2.5× faster)
  • Usable control range: ~25–80% contraction

7 · Known Trade-offs & Edge Cases

Noise floor vs. deadband

The 1.2 Ω span yields ≈ 0.012 Ω per 1% contraction. At the ADC's noise level (±1–2 counts after IIR filter), this translates to ±10–15% contraction noise. The 12% deadband is set just above this noise floor. Reducing FZ_DEAD_PCT below ~10% risks oscillation returning. The only way to reduce it further is to widen the IIR filter (lower α) or increase the sample count, both at the cost of slower response.

Rate anticipation uses one-tick delta

The rate term is measured[t] − measured[t−1] at 300 ms intervals, so it's actually a finite-difference velocity estimate. At the noise level, this is also noisy (up to ±30%/tick). The 10%/tick threshold filters most noise bursts, but a sustained upward noise run can trigger the rate guard. If this causes hunting, increase FZ_RATE_THRESH or apply a second IIR to the rate estimate.

Char-wire vs. closed-loop conflict

No mutex or ownership flag guards PWM access between MW_CharTick and MW_CLTick. Running both simultaneously will cause undefined PWM output. Mitigation: document "run set-per off before char-wire" in CLI help, or add a cl_active flag check at the start of MW_CharTick.

Buffer overflow in char profiler

char_buf holds 512 samples at 200 ms cadence = 102.4 s maximum. Phase timeouts (15 + 30 + 30 s = 75 s) are within budget, but if stability is never detected and phases run to timeout, total could approach the limit. The code checks char_count < CHAR_MAX_SAMPLES before writing, so it won't overflow — but the last samples will be silently dropped if the test runs very long.

printFloat0 rounding (known, not fixed)

TimbreOS printers.c has a rounding bug where values like 0.95 display as 0.5. This affects show-cl and show-cal output at certain values. The file is outside the mounted folder and was not modified in this session. Contraction values above ~5% are unaffected in practice.

8 · Test Checklist

Calibration

  • Run cal-wire with wire at room temperature — confirm no false warnings
  • Verify dR/R ≥ 5% reported in quality check
  • Run show-cal — confirm R_max ~8.9 Ω, span ~1.2 Ω
  • Run cal-wire with wire warm — confirm "not relaxed" warning fires (dR/R < 5%)

Zero-target (set-per 0 fix)

  • set-per 0 → wire should relax completely, PWM = 0%
  • show-cl → confirm measured = --, PWM = 0%, state idle/off
  • Leave for 30 s — wire must not drift warm
  • Then set-per 50 → confirm controller engages

Closed-loop stability

  • set-per 50 → settles without oscillation within 5 s
  • Apply load (push limb) → recovers to target within 3 s
  • set-per 80 → no spring snap overshoot on heating
  • set-per 30 → gentle cool-down, no sudden drop-and-snap
  • Step 30 → 70 → 30 three times — consistent response

Char-wire profiler

  • char-wire 25 → precool, heat, cool phases complete
  • Terminal shows phase transitions
  • dump-char → emits CSV with correct columns
  • Paste into spreadsheet — verify τ_heat ≈ 1.8 s, τ_cool ≈ 700 ms
  • Confirm char aborts gracefully if wire disconnected mid-run
Hold PWM field-tune procedure: With set-per 40, watch the wire for 60 s. If it slowly relaxes away from target, increment FZ_HOLD_PWM by 1 and rebuild. If it slowly creeps above target, decrement by 1. The sweet spot is where the wire holds position with minimal drift during the deadband phase.
